The FS PBX v1 API lets you manage accounts, extensions, users, and other PBX resources over HTTPS. Use your portal's hostname followed by `/api/v1`.

## Make your first request

In **Users**, edit the user your integration will use. Open **API Keys**, choose **Create API Key**, and copy the token. Send it in the `Authorization` header with each request. The API user needs access to the account and the permission listed for the endpoint.

For example, if your user has permission to list accounts, try this request. Replace the hostname and token with your own values.

```bash
curl 'https://pbx.example.com/api/v1/domains?limit=10' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Accept: application/json'
```

A successful response includes a `data` array. Use the appropriate entry's `domain_uuid` when an endpoint asks for the account UUID in its URL.

## Read the next page

Some lists return a page of results at a time. If the endpoint offers `starting_after`, use the last result to ask for the next page. For example, when listing accounts:

1. Request the first page with `GET /api/v1/domains?limit=10`.
2. If `has_more` is `true`, copy the **last** entry's `domain_uuid` from `data`. Request `GET /api/v1/domains?limit=10&starting_after=LAST_DOMAIN_UUID`, substituting that value.
3. Repeat with the last entry from each new page until `has_more` is `false`. Keep the same filters throughout.

Check the individual endpoint for its page size, sort order, and the value to use for `starting_after`. For example, **List users** sorts by user ID in ascending order. Pass the last user's `user_uuid` to continue.

## Handle errors

Check the HTTP status and the endpoint's documented error response. A `401` means you should check the API token. For a `403`, check the API user's account access and permissions. For a validation error, read the response for the field or value to correct.
